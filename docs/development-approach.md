# 개발 접근과 품질 원칙

ispacecraft는 브라우저 3D 프로젝트로 개발하고 있습니다. 공개 저장소에는 사용 안내·기획 방향과 피드백을 모으며 애플리케이션 소스 코드는 포함하지 않습니다.

## 브라우저와 시뮬레이션

현재 TypeScript와 Three.js를 사용합니다. 생존·비행·자원 등의 규칙 계산을 화면과 분리해, 실제 화면을 켜지 않고도 규칙을 검증할 수 있도록 구성합니다.

같은 시드·상태·입력의 재현성과 저장 후 복원, 직접 조종과 AI 항법이 사용하는 조건의 일관성을 중요하게 다룹니다. 기기와 버전이 달라도 모든 계산이 무조건 동일하다는 보장은 아니며, 각 기능에 필요한 범위를 검사합니다.

## 보이는 것과 규칙이 맞아야 합니다

착륙할 땅·물·채굴 대상·위험은 가능한 한 화면과 규칙이 같은 데이터를 기준으로 다룹니다. 표면 미세 무늬나 동식물처럼 시각적 표현만 제공하는 요소는 구분합니다.

광원·분사·그림자도 실제 동작 상태와 연결하는 방향으로 개선합니다. 모든 효과를 정밀 유체·광학 계산으로 구현한다는 뜻은 아닙니다.

## 거리와 기기에 맞는 상세도

먼 대상은 가볍게, 가까운 대상은 세밀하게 표시합니다. 많은 별·식물·위성을 각각 무거운 객체로 계산하는 대신, 필요한 정보와 실제로 식별할 수 있는 디테일에 비용을 씁니다.

화질 비교와 함께 프레임 시간·생성 지연·메모리와 자원 회수를 확인합니다. 특정 개발 기기에서의 측정값을 모든 휴대폰의 성능 보장으로 제시하지 않습니다.

## 자동 검증과 실제 화면 확인

- 생존·비행·채굴·정산·저장 호환 등 규칙을 자동 검사합니다.
- 긴 항해·궤도·착륙처럼 오래 걸리는 경로도 별도로 확인합니다.
- 브라우저에서 시작·이동·조종·저장·불러오기와 화면 전환을 확인합니다.
- 시각 효과는 고정 장면과 이동 장면, 화면 크기와 품질을 바꿔 비교합니다.

## 앞으로의 기술 선택

현재 기술을 기준으로 대표 장면에서 병목과 필요한 표현을 확인합니다. Rust/Wasm·WebGPU·다른 엔진으로의 전환은 확정된 출시 조건이 아닙니다.

AI 항법·자동 관리·상황별 버튼 추천이라는 명칭은 앱 안의 보조 기능을 가리킵니다. 외부 생성형 AI 서비스에 플레이 데이터를 전송하는 기능이라고 설명하지 않습니다.
